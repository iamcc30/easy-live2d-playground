# 三种语音监听模式功能说明

## ✨ 新功能概述

应用现在支持**三种语音监听模式**，您可以根据不同的使用场景选择最合适的模式。

## 📋 三种模式说明

### 🤖 Auto (自动停止)

**适用场景**: 日常对话、问答互动

**工作方式**:
- 开始录音后持续监听
- 服务器端检测到语音停顿后**自动停止**
- 自动发送已录制的音频进行处理
- 收到回复后可以再次点击录音

**优点**:
- ✅ 无需手动停止，体验流畅
- ✅ 适合一问一答的交互模式
- ✅ 避免录制过多无用内容

**使用流程**:
1. 点击麦克风按钮 🎤
2. 开始说话
3. 说完后停顿 → 自动检测停止
4. 等待AI回复

---

### 👆 Manual (手动停止)

**适用场景**: 长篇输入、复杂描述、多段表达

**工作方式**:
- 开始录音后持续监听
- 无论说多久都**不会自动停止**
- 必须**手动点击停止按钮**才会结束录音
- 发送完整的录音内容

**优点**:
- ✅ 可以说很长的内容，不被打断
- ✅ 中间可以有停顿和思考
- ✅ 完全由您控制录音时长

**使用流程**:
1. 点击麦克风按钮 🎤
2. 开始说话（可以有停顿）
3. 说完后再次点击麦克风按钮 🔴
4. 等待AI回复

---

### 📡 Realtime (持续监听)

**适用场景**: 实时对话、连续交互、同声传译

**工作方式**:
- 开始监听后**持续实时传输**
- 说话内容实时流式发送到服务器
- 无需停止，可以连续对话
- 适合多轮快速交互

**优点**:
- ✅ 最低延迟，实时响应
- ✅ 适合连续多轮对话
- ✅ 流式传输，边说边处理

**使用流程**:
1. 点击麦克风按钮 🎤
2. 持续说话，实时传输
3. 可以连续对话，无需重复点击
4. 需要停止时点击麦克风按钮

---

## 🎯 如何切换模式

### 位置
模式选择器位于**聊天输入框上方**（仅在WebSocket连接后显示）

### 操作步骤

1. **点击模式按钮**
   - 当前模式显示为：`🤖 auto` 或 `👆 manual` 或 `📡 realtime`

2. **选择模式**
   - 点击后弹出下拉菜单
   - 显示三个选项，每个都有详细描述
   - 当前模式会有 ✓ 标记

3. **应用模式**
   - 点击任意模式即可切换
   - 如果正在录音，会自动重启以应用新模式

## ⚙️ 技术细节

### 音频传输

所有模式都使用相同的音频传输机制：
- 采样率: 16kHz
- 声道: 单声道
- 编码格式: OPUS (优先) 或 PCM (回退)
- 帧间隔: 64ms
- 帧大小: ~128 bytes (OPUS) 或 ~2KB (PCM)

### 服务器端处理

不同模式对服务器端的要求：

**Auto模式**:
- 服务器需要实现VAD (Voice Activity Detection)
- 检测到停顿后触发停止事件
- 处理完整的音频段

**Manual模式**:
- 服务器等待客户端发送停止信号
- 缓冲所有音频数据
- 收到停止信号后开始处理

**Realtime模式**:
- 服务器需要支持流式处理
- 边接收边处理音频
- 实时返回结果

## 🔍 故障排查

### 问题 1: 看不到模式选择器

**原因**:
- WebSocket未连接
- 或使用的是本地语音识别模式

**解决**:
1. 确保点击了"连接"按钮
2. 等待状态显示"🟢 已连接"
3. 模式选择器会自动显示

### 问题 2: Auto模式一直不停止

**原因**:
- 服务器端VAD未正确配置
- 或背景噪音太大

**解决**:
1. 尝试切换到Manual模式手动控制
2. 或改善录音环境，减少背景噪音
3. 检查服务器端VAD配置

### 问题 3: Manual模式停止后无反应

**原因**:
- 可能是服务器处理延迟
- 或音频数据未完整发送

**解决**:
1. 等待几秒，服务器可能在处理
2. 查看控制台是否有错误日志
3. 检查网络连接

### 问题 4: Realtime模式延迟高

**原因**:
- 网络延迟
- 或服务器处理能力不足

**解决**:
1. 检查网络状况
2. 尝试使用Manual模式
3. 联系服务器管理员检查性能

## 📝 实现详情

### 客户端

监听模式通过 `ListenMessage` 的 `mode` 字段传递给服务器：

```typescript
interface ListenMessage {
  session_id: string
  type: 'listen'
  state: 'start' | 'stop' | 'detect'
  mode?: 'auto' | 'manual' | 'realtime'
}
```

### 服务器端

服务器需要根据 `mode` 字段实现不同的处理逻辑：

```python
async def handle_listen(message):
    mode = message.get('mode', 'auto')

    if mode == 'auto':
        # 启用VAD，检测停顿后自动停止
        await start_vad_detection()

    elif mode == 'manual':
        # 禁用VAD，等待客户端停止信号
        await buffer_audio_until_stop()

    elif mode == 'realtime':
        # 流式处理，实时传输结果
        await start_streaming_processing()
```
