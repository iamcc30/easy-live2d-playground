# 音频诊断系统使用指南

## ✅ 诊断系统已就绪

我已经为您创建了一个**自动诊断系统**来实时监控音频发送状态。

## 🚀 如何使用

### 1. 打开应用

应用已启动，请打开浏览器访问：

**本地访问**: http://localhost:5174/
**网络访问**: http://192.168.3.7:5174/

### 2. 查看诊断面板

您会在页面**左下角**看到诊断面板，包含以下信息：

#### 📋 诊断项目

- **WebSocket连接** - 显示连接状态
  - ✅ 已连接 = 正常
  - ❌ 未连接 = 需要点击"连接"按钮

- **麦克风权限** - 显示浏览器麦克风权限状态
  - ✅ 已授予 = 正常
  - ⚠️ 未请求 = 启动录音时会请求
  - ❌ 已拒绝 = 需要在浏览器设置中允许

- **音频API** - 显示浏览器支持情况
  - ✅ AudioContext + WebCodecs = 最佳（OPUS编码）
  - ⚠️ 仅AudioContext = 可用（PCM格式）
  - ❌ 不支持 = 浏览器不支持

- **录音服务** - 显示录音服务状态
  - ✅ 正在录音 = 音频正在采集
  - ⚠️ 未启动 = 点击麦克风按钮启动

#### 📊 实时传输统计

诊断面板会实时显示：

- **发送包数** - 已发送的音频包数量
- **发送字节** - 已发送的总字节数
- **平均间隔** - 音频包发送间隔（期望64ms）
- **传输速率** - 实时传输速率

### 3. 测试音频发送

按照以下步骤操作：

1. **点击"连接"按钮** （如果未连接）
   - 等待诊断面板显示 ✅ WebSocket连接: 已连接

2. **点击麦克风按钮** 🎤
   - 允许浏览器麦克风权限（如果弹出提示）
   - 等待诊断面板显示 ✅ 录音服务: 正在录音

3. **对着麦克风说话**
   - 观察诊断面板的"发送包数"是否增加
   - 观察控制台是否有 `📤 Sent audio data` 日志

### 4. 判断结果

#### ✅ 成功发送的标志

如果您看到以下任意一项，说明**音频数据正在发送**：

- 诊断面板的"发送包数"不断增加
- 诊断面板显示"✅ 音频数据正在发送！"
- 控制台有 `📤 Sent audio data: XXX bytes` 日志
- 平均间隔显示约 64ms

#### ❌ 未发送的标志

如果出现以下情况，说明**音频未发送**：

- 说话后"发送包数"仍然是 0
- 控制台看到 `❌ Cannot send audio: not connected`
- 诊断面板显示 ❌ WebSocket连接: 未连接

## 🔍 常见问题处理

### 问题 1: WebSocket未连接

**解决方法**：
1. 点击主界面的"连接"按钮
2. 检查 `.env.local` 中的 `VITE_WS_URL` 是否正确
3. 确认服务器 `ws://111.230.57.211:8888` 正在运行

### 问题 2: 麦克风权限被拒绝

**解决方法**：
1. Chrome: 地址栏左侧 → 网站设置 → 麦克风 → 允许
2. Firefox: 地址栏左侧 → 权限 → 麦克风 → 允许
3. Safari: Safari 菜单 → 偏好设置 → 网站 → 麦克风 → 允许

### 问题 3: 说话但没有数据发送

**可能原因**：
- 麦克风静音或音量太低
- 选择了错误的音频输入设备
- AudioContext被浏览器挂起

**解决方法**：
1. 检查系统音量设置和麦克风设置
2. 大声说话测试
3. 点击页面任意位置激活AudioContext

## 📱 移动端注意事项

如果在移动设备上使用：
- 诊断面板会自动调整大小
- 需要使用 HTTPS 才能访问麦克风
- 部分浏览器不支持 WebCodecs（会自动降级到PCM）

## 🎯 确认音频发送的最终方法

### 客户端确认

1. **诊断面板**："发送包数" > 0 且持续增加
2. **控制台日志**：持续出现 `📤 Sent audio data`
3. **Network标签**：WS → Messages → 看到绿色箭头 ⬆️

### 服务器端确认

在您的服务器代码中添加日志：

```python
async for message in websocket:
    if isinstance(message, bytes):
        print(f"🎵 Received audio: {len(message)} bytes")
```

如果服务器打印了这条日志，说明**音频确实被发送并接收**。
